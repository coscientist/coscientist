- Better Auth runs `sendVerificationOTP` through `runInBackgroundOrAwait`, which catches every error, logs `Failed to run background task`, and answers 200 `{"success":true}`; a new mail path inside a Better Auth callback adds the request context to `failedSignInSends` in `lib/auth.ts`, or its delivery failures read as success.
- Leave non-sign-in OTP types out of `failedSignInSends`: Better Auth calls the sender for them only when the account exists, so a 503 there tells a caller which emails have accounts.
- Better Auth trusts only the origin of `baseURL` (`BETTER_AUTH_URL`), `trustedOrigins`, and `BETTER_AUTH_TRUSTED_ORIGINS`, and `lib/auth.ts` sets neither of the last two, so sign-in from a Vercel preview URL that differs from `BETTER_AUTH_URL` answers 403 `{"code":"INVALID_ORIGIN"}`; a preview that must sign in sets `BETTER_AUTH_URL` to its own origin or sets `BETTER_AUTH_TRUSTED_ORIGINS`, and passkeys there also need that hostname, because `rpID` comes from `BETTER_AUTH_URL`. [source: https://github.com/coscientist/coscientist/pull/3]
- `disabledPaths` in `lib/auth.ts` names each blocked email OTP path by exact string, so after a `better-auth` bump diff the paths registered in `node_modules/better-auth/dist/plugins/email-otp/routes.mjs` against the list and probe each unlisted path with `curl -X POST`; a disabled path answers 404. [source: https://github.com/coscientist/coscientist/pull/3]
- Reject a sign-up with `throw APIError.from(...)` in `hooks.before`, as the `DISPOSABLE_EMAIL` check does: returning `false` from `databaseHooks.user.create.before` makes `/sign-in/email-otp` answer 500 `Cannot read properties of null (reading 'id')`, and `user.validateUserInfo` makes `testUtils().saveUser` in `.devcontainer/seed.ts` throw 403 `validation_context_missing`.
- The passkey endpoints fall under the global rate-limit rule (100 requests per 10 seconds), not the 3 per 60 seconds of the email OTP paths, so a passkey limit needs `customRules`.
- Passkey registration needs a session younger than `freshAge` (86400 seconds), else it answers 403 `SESSION_NOT_FRESH`.
- The passkey plugin never creates a user, so a passkey-first sign-up needs `registration.resolveUser` code.
